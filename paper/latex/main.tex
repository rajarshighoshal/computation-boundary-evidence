\begin{abstract}
A repair agent with shell tools must reconstruct a repository's computational structure from text search. CBE (computation and boundary evidence) prepares that structure once and lets the agent query it during repair, under the same model and budget. On 89 held-out SWE-bench Science tasks ($k{=}3$), both arms solve 60 attempts (22.9\% vs.\ 23.1\%). Aggregate parity masks a discipline-level split: mechanics +22.2\,pp, materials +9.7\,pp, astronomy +12.4\,pp; biomedical engineering $-$16.7\,pp, biology $-$9.5\,pp. CBE generates 13.7\% fewer output tokens. About a fifth of tasks flip between identical runs, bounding what any single-run comparison can resolve.
\end{abstract}

\section{Introduction}
Repairing a composite-laminate stiffness calculation requires changing both the ply iteration and the accumulation formula. Expanding one without the other passes the public check but fails the private tests. The patch is short; finding it means knowing which expression produces the returned matrix and what calls cross the repository boundary.

We evaluate whether providing this structure directly changes repair outcomes. CBE exposes source-linked computation structure; the baseline reconstructs the same context from grep and file reads. Same model, same budget.

Contributions: the preparation pipeline, the query interface, and a replicated evaluation that separates discipline-level differences from aggregate noise.

CBE draws on traceability~\citep{niu2023ablots,niu2023rat,niu2025tvr,pan2025coverage}, code property graphs~\citep{yamaguchi2014cpg}, scientific model extraction~\citep{pyarelal2020automates,skema2024gromet}, and incremental parsing~\citep{treesitter2024}. We evaluate on SWE-bench Science~\citep{xu2026science} with DeepSeek V4.1 Flash~\citep{deepseek2026}; SWE-bench~\citep{jimenez2024swebench,yang2024swebenchverified} and SciCode~\citep{tian2024scicode} are related benchmarks.

\section{What CBE provides}
\label{sec:method}
\paragraph{Prepare.}
Run the public \texttt{reproduce.py} under an observer. Observed functions guide file selection. Static extraction adds expressions, conditions, definitions, and call boundaries without model calls. Median duration: \MedianPreparation{}\,s of the 1800\,s budget.

\paragraph{Represent.}
Tree-sitter~\citep{treesitter2024} parses Python ASTs for scopes, assignments, binary expressions, return anchors, and branches. Joern handles C, C++, Fortran, and Cython where available; explicit fallback otherwise. External calls are labelled with their provider as interface assumptions, not correctness guarantees. Unresolved callees stay \texttt{unknown\_external}.

\paragraph{Query and repair.}
The agent accesses three endpoints alongside shell utilities:
\texttt{find} searches extracted symbols, expressions, and docstrings;
\texttt{inspect} retrieves computation scopes, dependencies, and boundary assumptions;
\texttt{note} records an explicit working model into a durable scratchpad without gating repair actions.
Inspection dynamically refreshes edited source lines, while preparation traces remain fixed.

Mechanics: +22.2\,pp, entirely task 103 (pyNastran). The agent inspects the ply-angle computation and its numpy boundaries, then edits --- 2/3 solves vs.\ 0 baseline. Materials: +9.7\,pp across three tasks. Astronomy: +12.4\,pp.

Biomedical engineering: $-$16.7\,pp across four tasks. Task 022 (nilearn): baseline solves 2/3, CBE 0/3. The trajectory reads projection mathematics before touching the atlas-label mapping. Biology: $-$9.5\,pp. The two $-$33.3\,pp domains are singletons.

When the defect is a computation, structure finds it. When an ordinary bug sits under scientific prose, structure distracts.

\paragraph{Replication stability.}
Most tasks never solve or always solve across repeated runs; about a fifth flip within an arm (Figure~\ref{fig:replication}).

\begin{minipage}{\columnwidth}
\centering
\includegraphics[width=\columnwidth]{figures/replication.pdf}
\captionof{figure}{Within-arm outcome stability across 3 repeated seeds. Most tasks are deterministically solved or unsolved; 18--20\% flip between runs.}
\label{fig:replication}
\end{minipage}

Across the 89 tasks, 60 never solve in either arm, 11--12 solve in all three runs, and 16--18 yield mixed outcomes. This within-arm stochasticity bounds single-run benchmark resolution: differences smaller than $\sim$5\,pp fall within stochastic run-to-run noise.

\section{Limitations and conclusion}
\label{sec:conclusion}
One model, one effort, one budget. Domain analyses are descriptive; singleton domains carry no weight. The store is approximate: unparseable expressions are recorded as unsupported, external calls are labelled rather than verified. No ablations isolate which part of CBE matters.

CBE reaches parity, generates fewer tokens, and splits the benchmark by discipline. Scientific structure helps when the defect is a computation and hurts when it is ordinary code.

\paragraph{Artifacts and AI use.}
The author designed the study; LLM assistants (Oh My Pi, ChatGPT) helped implement the harness and revise prose. DeepSeek V4.1 Flash~\citep{deepseek2026} was the only repair model.
