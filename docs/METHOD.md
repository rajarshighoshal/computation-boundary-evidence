# Method and experimental boundaries

## What the three stages mean

Alignment compares an extracted scientific expression with a source-corroborated implementation expression under explicit symbol bindings. It reports ordered structural differences. Expressions are not automatically reordered or declared numerically equivalent.

Semantic lifting recognizes a few operation patterns and associates them with candidate scientific meanings only under supplied evidence and assumptions: unit conversion, weighted reduction/integration, normalization and linear transformation. A generic sum is not automatically an integral; Python's builtin sum is not treated as a full scalar reduction.

Propagation calculates consequences of supported dimension, formal multiplicative-factor and shape anchors. It preserves uncertainty. Algebraic scale cancellation does not establish floating-point equality; unequal additive coefficients do not imply a physical-unit error. Unsupported symbolic extents do not become concrete shape conflicts.

## Public interface

The canonical JSON schema is generated by `scicontext schema`. Expression trees use symbol/constant/ordered-operator/unknown nodes. Source-derived actual expressions must correspond uniquely to cited indexed expression spans and hashes; otherwise the handoff labels them uncorroborated and excludes them from code-derived analysis.

The immutable original task is made available outside the patch tree. Its evidence name is `@context/task_statement.md`. This special source is read only from the explicitly supplied context directory; arbitrary context paths are rejected.

Source indexing initially supports Python. Scoped import resolution and branch metadata are conservative syntactic evidence, not complete dynamic dispatch, alias analysis or dataflow proofs. Other languages remain in scope for LLM inspection; mechanical coverage is reported explicitly.

## Timing and isolation

The extraction and repair passes use separate fresh Codex sessions and separate task environments. Only the validated graph handoff crosses from extraction to repair. The parent controller owns one monotonic deadline, and all preparation-stage helpers count toward the extraction cap and total allowance.

In the bounded revision, code prepares evidence concurrently with interpretation. The LLM supplies compact semantic annotations and optional independent probe scripts; code owns citation resolution, graph construction, validation and probe execution. Interpretation has an earlier deadline than probes/assembly; collection reserves time for bounded container shutdown. The LLM's final acknowledgement is only a filename. See `EXTRACTION_V2.md` for the exact interface and `EXTRACTOR_VERIFICATION.md` for the separate development checks.

GNU `timeout` bounds each ordinary foreground Codex process group, with time reserved for collection. It is not a guarantee against deliberately detached children. The separate extraction container is stopped after collection; Pier runs the original artifact hook and verifier for repair. Raw outputs, timeout exits, collection overhead and any total overrun are retained.

The adapter calls the upstream Pier `Codex.run` implementation for both passes, retaining its launch, subscription authentication, proxy handling, native tools and cleanup. A plain final-message file and small GNU-timeout launcher are retained; the graph output-schema flag is removed. Docker is the isolation boundary, following the [documented Codex container setup](https://learn.chatgpt.com/docs/agent-approvals-security#run-codex-in-dev-containers). Credentials inside the container are not hidden from its commands.

The extractor is instructed not to modify source and operates on a disposable task copy. The handoff is rejected if tracked source changes or unexpected untracked files are detected (task outputs are excluded). The repair candidate is a separate untouched copy. This is an experimental check, not a custom OS sandbox or a security guarantee against a malicious agent.

## Interpretation

This two-arm study estimates the complete bounded workflow's effect against ordinary Codex. It does not isolate the graph format, analysis prompts, helper rules or session handoff as a causal mechanism. Equal elapsed-time limits do not imply equal tokens, so both are reported.

Foundational influences: [AutoMATES](https://arxiv.org/abs/2001.07295), [SKEMA](https://github.com/ml4ai/skema), [semantic enrichment of dataflow graphs](https://arxiv.org/abs/1807.05691), [Phys](https://unl-nimbus-lab.github.io/phys/), and [CamFort units](https://arxiv.org/abs/2406.02174). Close repair/harness precedents include [SpecRover](https://arxiv.org/abs/2408.02232), [DSrepair](https://arxiv.org/abs/2502.09771), and [SIGA](https://arxiv.org/abs/2606.09774). The implementation is a bounded custom prototype inspired by these mechanisms, not a port or reproduction of their entire systems.
